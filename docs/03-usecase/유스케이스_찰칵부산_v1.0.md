### 5.3 유스케이스 관계

| 관계 | 방향 | 조건 (확장점) | 근거 |
|---|---|---|---|
| `<<extend>>` | UC-03 → UC-01 | GPS가 없는 사진이 있을 때 ("위치 없는 사진") | FR-06 |
| `<<extend>>` | UC-05 → UC-04 | 여행자가 핀이나 방문지 카드를 누를 때 ("장소 선택") | UI-06 |
| `<<extend>>` | UC-07 → UC-06 | 여행자가 여행기를 편집할 때 ("편집") | FR-10 |
| `<<include>>` | UC-06 → UC-09 | 항상 (여행기 생성 후 출처 연결·대조) | FR-09, AIR-06 |
| `<<include>>` | UC-07 → UC-09 | 항상 (다시 쓰기·편집 후 대조) | FR-10, AIR-06 |

UC-09를 따로 둔 이유: 출처 각주 연결과 공식 데이터 대조는 여행기 생성(UC-06)과 편집(UC-07)에서 똑같이 쓰인다. 설계서에서도 대조는 CP-14 Fact Checker, 각주 연결은 CP-13 Story Generator가 맡아 두 흐름이 같은 컴포넌트를 쓴다 (설계서 3.2절).

### 5.5 유스케이스 명세

#### UC-01 사진 업로드·방문지 분석

| 항목 | 내용 |
|---|---|
| 주 액터 | 여행자 |
| 보조 액터 | — |
| 관련 요구사항 | FR-01, FR-02 · NFR-01, NFR-04 · UI-01, UI-02, UI-03 · DR-08 |
| 관련 화면 | A1 홈, A2 사진 선택, A3 분석 중 |
| 사전조건 | 여행자가 모바일 웹에 접속했고, 부산 여행 사진이 기기 갤러리에 있다. 사진을 AI로 분석하는 데 동의했다 (NFR-04) |
| 사후조건 | 방문지가 만들어진다(상태: 분석중). 원본 사진은 임시로만 보관되고 분석이 끝나면 삭제된다 (DR-08) |
| 확장점 | "위치 없는 사진" (5단계) → UC-03 |

**기본 흐름**
1. 여행자가 홈에서 새 여행기를 시작한다.
2. 여행자가 갤러리에서 사진 1~30장(JPEG, HEIC, PNG, 장당 20MB 이하)을 고른다.
3. 시스템이 장수·형식·크기를 검사하고 사진을 올린다.
4. 시스템이 사진마다 촬영 시각과 GPS 좌표를 추출하고, "위치 있음 N장 · 없음 M장"을 보여 준다.
5. 시스템이 시간·거리 기준으로 사진을 방문지로 묶고, 방문지별 중심 좌표와 시간대를 계산해 날짜별로 나눈다.
6. 시스템이 분석 단계별 진행률과 남은 시간을 보여 주고, 이미 묶인 방문지를 지도에 먼저 보여 준다.
7. 방문지 묶기가 끝나면 UC-02로 이어진다.

**대안·예외 흐름**
- 2a. 31장 이상을 고르면 시스템이 업로드를 막고 안내한다.
- 3a. 지원하지 않는 형식이거나 20MB를 넘는 사진은 제외하고 여행자에게 알린다.
- 4a. 촬영 시각도 위치도 없는 사진은 "정보 없음"으로 표시하고, 분석에서 제외할지 여행자에게 묻는다.
- 5a. 위치가 없는 사진이 있으면 UC-03을 수행한다.
- 5b. 위치 있는 사진이 하나도 없으면 촬영 시각만으로 방문지를 묶고, UC-02에서 모든 방문지를 선택필요로 두어 여행자가 직접 검색으로 장소를 지정한다 (FR-02).
- 6a. 여행자가 화면을 떠나도 분석은 계속되고, 다시 접속하면 진행 상태나 완료 결과를 보여 준다 (UI-03).

#### UC-02 방문지 장소 확정

| 항목 | 내용 |
|---|---|
| 주 액터 | 여행자 |
| 보조 액터 | 관광 데이터 API, AI 모델(VLM) |
| 관련 요구사항 | FR-03, FR-04, FR-05 · NFR-02, NFR-05, NFR-08 · UI-04, UI-05 · AIR-01~04, AIR-07 · DR-02, DR-09 |
| 관련 화면 | B1 방문지 목록, B2 장소 확인, B4 확정 완료 |
| 사전조건 | UC-01에서 방문지가 만들어졌다 |
| 사후조건 | 모든 방문지가 자동확정·확정·기타장소 중 하나가 된다. 여행자가 고른 결과는 매칭 로그로 저장된다 (DR-09). 분석 작업이 끝나면(성공·실패 무관) 원본 사진과 사진 좌표가 삭제된다 (DR-08, AC-09) |

**기본 흐름**
1. 시스템이 방문지 중심 좌표 반경 300m 안의 장소를 관광 데이터 API에서 찾는다. 이미 조회한 공공데이터 장소는 장소 캐시를 쓴다(카카오 로컬 결과는 운영정책상 캐시하지 않는다).
2. 시스템이 방문지 대표 사진 1장(축소본)과 후보 목록을 AI 모델(VLM)에 보내고, 선택한 장소·확신도·판단 근거를 받는다.
3. 시스템이 응답의 장소가 후보 목록 안에 있는지, 형식이 맞는지 검사한다.
4. 시스템이 확신도에 따라 방문지 상태를 정한다: 0.8 이상은 자동확정, 0.5 이상 0.8 미만은 확인필요, 0.5 미만은 선택필요.
5. 시스템이 방문지 목록을 보여 주고, 확인필요·선택필요인 방문지만 여행자에게 묻는다.
6. 여행자가 방문지를 열면 사진, 후보 목록(촬영 위치와의 거리, 출처), AI 추천과 판단 근거를 본다.
7. 여행자가 후보 하나를 고르면 방문지가 확정되고, 매칭 로그가 저장된다.
8. 묻는 방문지가 모두 처리되면 시스템이 확정 완료 화면을 보여 준다.

**대안·예외 흐름**
- 1a. 300m 안에 후보가 없으면 600m로 넓혀 다시 찾는다. 그래도 없으면 선택필요로 두고, 6단계에서 직접 검색과 "기타 장소"를 제공한다.
- 1b. 외부 API 호출이 실패하면 2회 재시도한다. 그래도 실패하면 해당 방문지만 선택필요로 넘기고 나머지 방문지는 계속 처리한다 (NFR-08, 설계서 QA-06).
- 2a. AI 모델이 맞는 후보가 "없음"이라고 답하면 선택필요로 둔다 (AIR-02).
- 3a. 장소가 후보 목록에 없거나 형식이 틀리면 1회 다시 요청한다. 다시 실패하면 선택필요로 둔다 (AIR-03).
- 7a. 후보 중 맞는 장소가 없으면 여행자가 직접 검색해 고르거나 "기타 장소"로 저장한다.
- 7b. 자동확정된 방문지도 여행자가 열어 바꿀 수 있다. 바꾸면 상태가 확정이 된다.

**특기 사항**
- VLM은 사진 속 인물을 분석하거나 설명하지 않는다 (AIR-04, NFR-04).

#### UC-03 위치 없는 사진 배정

| 항목 | 내용 |
|---|---|
| 주 액터 | 여행자 |
| 보조 액터 | AI 모델(VLM) |
| 관련 요구사항 | FR-06 |
| 관련 화면 | B3 위치 없는 사진 |
| 사전조건 | GPS가 없는 사진이 있고, 다른 사진으로 방문지가 묶여 있다 |
| 사후조건 | 여행자가 확인한 사진이 방문지에 배정된다 |
| 관계 | UC-01을 확장한다 (확장점 "위치 없는 사진") |

**기본 흐름**
1. 시스템이 위치 없는 사진의 촬영 시각이 어느 두 방문지 사이인지 보고, 해당 방문지를 추천한다.
2. 시스템이 사진마다 추천 방문지와 추천 이유를 보여 준다.
3. 여행자가 추천을 확인하면 사진이 그 방문지에 배정된다.

**대안·예외 흐름**
- 1a. 촬영 시각만으로 정하기 애매하면 AI 모델(VLM)이 인접 방문지의 사진과 비교해 추천한다.
- 3a. 여행자가 다른 방문지를 고르거나, 배정하지 않고 남겨 둘 수 있다.

#### UC-04 동선 확인

| 항목 | 내용 |
|---|---|
| 주 액터 | 여행자 |
| 보조 액터 | 카카오맵, 관광 데이터 API(선택 흐름) |
| 관련 요구사항 | FR-07, FR-12(S) · UI-06 · NFR-08 |
| 관련 화면 | C1 동선 지도, C2 타임라인, C4 근처 못 가본 곳 |
| 사전조건 | 방문지의 장소가 확정됐다 (UC-02) |
| 사후조건 | — (조회 기능) |
| 확장점 | "장소 선택" (5단계) → UC-05 |

**기본 흐름**
1. 여행자가 동선 지도를 연다.
2. 시스템이 카카오맵 위에 방문 순서대로 핀과 경로를 그린다. 핀은 장소 유형별 색과 방문 순서 번호로 구분한다.
3. 시스템이 방문지 사이 이동 시간을 계산해 타임라인으로 보여 준다.
4. 여행자가 1일차·2일차·전체 보기를 전환한다.
5. 여행자가 핀이나 방문지 카드를 누르면 UC-05를 수행한다.

**선택 흐름 (FR-12, 우선순위 S)**
- 4a. 여행자가 "근처 못 가본 곳"을 누르면, 시스템이 방문지 주변 공식 데이터 장소 중 이번 여행에서 가지 않은 곳 2~3곳을 거리순으로 보여 준다(이름, 유형, 거리, 출처).

**예외 흐름**
- 2a. 지도나 경로를 불러오지 못하면 오류를 안내하고 다시 시도할 수 있게 한다.

#### UC-06 여행기 생성

| 항목 | 내용 |
|---|---|
| 주 액터 | 여행자 |
| 보조 액터 | AI 모델(LLM) |
| 관련 요구사항 | FR-09 · NFR-03, NFR-08 · AIR-05, AIR-06 · UI-07 · DR-05, DR-06 |
| 관련 화면 | D1 문체 선택, D2 여행기 |
| 사전조건 | 모든 방문지가 자동확정·확정·기타장소 중 하나다 |
| 사후조건 | 여행기와 각주가 저장된다 |
| 포함 | UC-09 (3단계) |
| 확장점 | "편집" → UC-07 |

**기본 흐름**
1. 여행자가 여행기 만들기를 누르고 문체(블로그형 등)를 고른다.
2. 시스템이 확정된 방문지와 장소 공식 정보만 AI 모델(LLM)에 넣어 여행기를 생성한다. 문장마다 근거 장소 ID를 표시하게 한다.
3. 시스템이 UC-09를 수행해 사실 문장에 출처 각주를 연결하고, 입력 데이터와 대조한다.
4. 시스템이 제목, 본문, 날짜별 동선 요약, 각주 목록을 보여 주고, AI가 작성한 글임을 표시한다.
5. 여행자가 장소 이름을 누르면 장소 상세로, 각주 번호를 누르면 하단 출처 목록으로 이동한다.

**대안·예외 흐름**
- 2a. 생성에 실패하면 오류를 안내하고 다시 시도할 수 있게 한다.
- 3a. 근거가 없는 사실 문장은 경고를 표시하거나 제거한다 (AIR-06).
- 5a. 여행자가 편집을 선택하면 UC-07을 수행한다.

#### UC-07 여행기 편집·사실 대조

| 항목 | 내용 |
|---|---|
| 주 액터 | 여행자 |
| 보조 액터 | AI 모델(LLM) |
| 관련 요구사항 | FR-10 · AIR-06 |
| 관련 화면 | D3 편집 · 사실 대조 |
| 사전조건 | 생성된 여행기가 있다 (UC-06) |
| 사후조건 | 수정한 여행기가 저장된다 |
| 관계 | UC-06을 확장한다 (확장점 "편집"), UC-09를 포함한다 |

**기본 흐름**
1. 여행자가 여행기에서 문단을 고르고 다시 쓰기를 요청한다.
2. 시스템이 그 문단만 AI 모델(LLM)로 다시 생성하고, UC-09를 수행해 각주를 연결한다.
3. 여행자가 문장을 직접 편집한다.
4. 시스템이 UC-09를 수행해 편집한 문장을 공식 데이터와 대조한다.
5. 운영시간, 위치 등 공식 데이터와 다른 사실이 있으면 해당 문장에 경고를 표시한다.
6. 여행자가 문장을 고치거나 그대로 두고 저장한다.

**대안·예외 흐름**
- 1a. 다시 쓰기 없이 바로 3단계(직접 편집)로 갈 수 있다.
- 2a. 다시 생성에 실패하면 기존 문단을 유지하고 오류를 안내한다.
